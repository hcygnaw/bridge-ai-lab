## 二、各关设计思路与本地测试结果

### 第 1 关「小水沟」—— `3,777 / 10,000`（3/3 通过）
- **设计思路**：15m 跨度、无水下支点。采用 6 段 `road`（每段 2.5m）+ 下倾式 Pratt 木桁架（`wood` 仅在受拉斜杆或短受压弦杆内避免受压欧拉屈曲 `buckle/L²` 失稳），并在后期通过 `prune_opt.py` 进行构件删减和坐标微调。
- **本地测试**：`python3 bridge.py run 1 submission/level1.json -q` -> `3/3 通过`（`sample1`、`sample2`、`sample3`）。

### 第 2 关「大峡谷」—— `14,655 / 26,000`（2/2 通过）
- **设计思路**：30m 深谷，利用谷壁锚点 `A1`、`A5` 构建抛物线形钢拱（`steel` 受压拱肋 + 短弦长以避开 `900/L²` 屈曲限制）支撑桥面，后期经 `prune_opt.py` 删去冗余杆件并将部分辅助斜杆降级为 `wood` 与 `cable`。
- **本地测试**：`python3 bridge.py run 2 submission/level2.json -q` -> `2/2 通过`（含超载面包车场景）。

### 第 3 关「早高峰」—— `8,949 / 18,000`（3/3 通过）
- **设计思路**：28m 跨度、中墩 `A2=(14,-4)` 可用。采用双跨下斜拉/桁架组合结构，借用中央墩台把单跨折半为两个 14m 跨，大幅降低内力峰值；后期经 `prune_opt.py` 将大量钢杆降级为木杆并精简腹杆。
- **本地测试**：`python3 bridge.py run 3 submission/level3.json -q` -> `3/3 通过`（早高峰 A、面包车车队、对开车流）。

### 第 4 关「过船」—— `16,904 / 25,000`（2/2 通过）
- **设计思路**：利用两侧桥台及下锚点在 `x=7.5` 与 `x=16.5` 处分别悬挑伸出对称双叶开启桥（bascule drawbridge），以 `horn` 传感器触发 `lights` 拦车（并在合适延时后放行）与 `hydraulics` 同步起升/复位，跨过 `[9, 15] x [-2, 6]` 航道。后期在 `prune_opt.py` 上开启节点坐标下降与杆件删减/降级，从 `23,939` 降至 `16,904`（所有场景零断裂，峰值应力 `99.5%`）。
- **本地测试**：`python3 bridge.py run 4 submission/level4.json -q` -> `2/2 通过`。

### 第 5 关「钱不够」—— 未通过（未生成 `submission/level5.json`）
- **尝试过的思路**：
  1. 左侧 10.5m 深坑用 `A5/A4` 支撑的 `Y-frame` 钢架（约 `4,400`），24m 河道用深腹 `road` 悬链线配多组 `cable` 斜拉索（`ks=(2,3)` 与 `ks=(4,)`）：`ks=(4,)` 总造价 `9,608` 在 `sample1` 中成功放行小轿车，但 2,400 kg 面包车穿过悬链谷底时路面拉力达 `90.7~92.2 kN`，略超 `90 kN` 上限；`ks=(2,4)` 则超出 `10,000` 预算且局部动力冲击拉断斜索。
  2. 尝试用深坑 `road` 悬链线（省去 `Y-frame` 约 `2,600` 费用）或 `2` 根钢撑 + 跳坡，受限于两端路面斜率过大导致车辆翻车/触地或 `road` 超长/超拉，最终未在预算内同时稳定通过 `sample1` 和 `sample2`。
  3. 尝试利用 `water_y = -8` 深度进一步下沉河道悬链线（`y_mid = -4.2 ~ -5.8`）以及静态滑雪跳台飞跃方案，因倾角过陡擦底（`VFAIL 2`）或钢梁超预算未能成型。

### 第 6 关「地狱关」—— `18,839 / 20,000`（3/3 通过）
- **设计思路**：36m 三跨 + 5000 kg 卡车 + 船只通行 + 严格 `20,000` 预算。采用 `[0,12]` 与 `[24,36]` 两侧钢木组合弓弦拱（steel 拱肋 + wood 竖杆 + 交叉斜索）固定桥塔与引桥，在 `x=12` 和 `x=24` 直接铰接 4 段式对称开启桥叶（`ratio=0.50, speed=3.0, accel=2.0`），`horn` 触发后 `2.5s` 红灯拦车、`6.0s` 抬桥、`16.2s` 落下、`18.2s` 绿灯放行。初版为 `19,957.23`（零断裂），经 `prune_opt.py` 删减冗余钢索并降级为木杆后降至 `18,839`。
- **本地测试**：`python3 bridge.py run 6 submission/level6.json -q` -> `3/3 通过`（船 16 秒卡车先、船 24 秒车流、船 14 秒卡车右来）。

### 第 7 关「攻防决赛」
- **守方 `submission/final_bridge.json`（`25,892 / 26,000`）**：
  - 14 段 `4.0m` 高抛物线弓弦钢拱（`A0 -> A3`），钢竖杆与斜腹杆、两端 `A1/A4` 斜撑及沿桥面平行布置抗拉 `cable` 系杆。
  - 无捣蛋车测试：`python3 bridge.py run final submission/final_bridge.json -q` -> `1/1 通过`（车队峰值应力 `68.1%`）。
  - 对战己方捣蛋车：`python3 bridge.py duel submission/final_bridge.json submission/saboteur.json` -> **桥方胜**（仅 1 根杆件断裂，后续 4 辆车队全部安全到达）。
- **攻方 `submission/saboteur.json`（`2,497 kg`，`5,183 / 6,000`）**：
  - `10 m/s` 满速三轮底盘（轮距 3.0m），于第 4 节点装载 `1,865 kg` 集中配重，配 2 根 `hydraulics` 构成肘节冲击锤，由 `mygate` 触发（`x=20.0, 22.0` 处收缩 `ratio=0.77` 后 `0.35s` 复位）在跨中制造瞬态冲击载荷。
  - 本地 `duel` 测试：对基线 16 跨钢下承式桁架（`25,881`）可在 `3.4s` 击断多达 10+ 根杆件使车队坠毁并由己方捣蛋车在 `< 12s` 完好冲线；对抗己方重甲弓弦拱 `final_bridge.json` 时于 `5.8s` 完好冲线并打断 1 根杆件。

## 三、规则理解难点与潜在歧义

1. **「过车后杆件断裂仍算过关」的判定边界**：`RULES.md` 提到“只要全部车辆都按时完好到达，就算通过 —— 哪怕过桥之后某些构件断了”。在优化 L1 与 L6 时，`prune_opt.py` 找到的极低造价解会出现某根辅助杆件在车辆接近终点或刚通过后断裂（`peak=900%`）但 `bridge.py` 明确判为 `[通过]`。赛前如果能更清晰地界定是否会对隐藏场景的时序产生影响，会更稳妥。
2. **第 5 关描述中的坑深与河水高度**：关卡描述重点强调“4 米深、10.5 米宽的旧码头坑”，容易让人误以为河面也在 `-4m`，实际 `level5.json` 中 `water_y = -8`、`build_area.y = [-6, 14]`，查看 JSON 后才发现河道下方其实有到 `-6m` 的可用空间。
3. **第 7 关捣蛋车液压限制差异**：桥梁侧液压杆支持 `speed <= 15.0`、`accel <= 120.0`，而 `saboteur.json` 的液压杆参数限制明显更紧（`speed <= 3.0`、`accel <= 5.0`），需通过 `saboteur.py` 校验而非套用桥梁液压参数。

## 四、怀疑的模拟器现象与工程观察

1. **欧拉受压屈曲平方衰减极其陡峭**：`bridge_sim.cpp` 中受压上限 `min(comp, buckle / L²)` 使长木杆和长钢杆的抗压能力随长度平方迅速崩塌（如木杆 `L=3.0m` 时抗压仅 `13.3 kN`），因此斜腹杆方向（Pratt 受拉 vs Howe 受压）对结构承载力具有决定性影响。
2. **轴力断裂采用 EMA 滤波（`BREAK_TAU = 0.1s`）**：瞬时尖峰力如果不持续约 0.1s 不会立即拉断构件；这使攻方捣蛋车单纯依靠普通行驶很难击穿强桥，必须依靠肘节机构或集中质量制造持续冲击脉冲，同时也解释了为何车辆落坡瞬间的短促冲击有时可被吸收。
3. **Linux 环境下默认编译输出文件名**：`bridge/build_engine.py` 编译出的原生可执行文件仍命名为 `bridge_sim.exe`，在 Linux 工作区中可正常直接执行；所有物理与校验均以同目录下该二进制为准。
